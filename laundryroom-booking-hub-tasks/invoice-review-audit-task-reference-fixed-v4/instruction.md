Some invoices in the manager screen are stale: saved balance, status and payment history do not always agree. Add a review layer instead of fixing this inside the page. Put the public API at `@/lib/invoice/review`, exporting `InvoiceReviewNormalizer.normalize`, `InvoiceReviewQueryService.query`, `InvoiceReviewSummaryService.summarize` and `InvoiceReviewCsvService.export`. Keep all four operations pure.

Normalize `invoiceNumber,customerName,mainServiceName,branchId` by trimming/collapsing whitespace. Keep an id or use one-based `invoice-<position>`. `totalBill,paidAmount,balance` accept finite numbers or numeric strings, including commas; invalid values become null. Statuses are `pending,balance,cleared,cancelled`, case-insensitive; invalid status is null. Convert valid `Date`/Firestore-style timestamps to ISO and invalid dates to null. `expectedBalance=totalBill-paidAmount`; `outstanding` is never negative.
