Make candidate restaurant approval and rejection race-safe, atomic, and batchable.

`PUT /api/v1/candidate-restaurants/:candidateRestaurantId/approve` and `.../reject` run in one transaction. Approval creates the restaurant, finds or creates its chain from the name before `" | "` without duplicating an existing chain, marks the candidate approved, and when a submitter exists adds 20 incentive points plus one `General` history entry, creating the incentive row if needed. Ownerless candidates approve without touching incentives. A linked candidate admin gets an admin account, credentials email, chain assignment only when the chain has no admin, and approval; if that admin was already approved, return 409 containing `already approved` and roll back every write. Rejection marks the candidate and linked candidate admin rejected and creates no restaurant. Any failure, including email or notification persistence, rolls everything back. Lock each candidate; concurrent reviews serialize to one 200 and one 409 stating the candidate is already approved or already rejected. Unknown return 404 with `Candidate Restaurant not found`; finalized return 409 with `Candidate Restaurant already approved` or `Candidate Restaurant already rejected`. Keep the admin guard and its 401.

Both endpoints return 200 as `{"success":true,"data":{"candidateRestaurantId":"<id>","action":"approve|reject","is_approved":<bool>,"is_rejected":<bool>,"restaurant_id":"<id>|null"}}`. Errors use `{"success":false,"message":"<text>","statusCode":<status>}`.

On success, write one notification per admin naming the restaurant, with the acting admin as actor. Add `PUT /api/v1/candidate-restaurants/review-batch` with `{"items":[{"candidateRestaurantId":"<id>","action":"approve|reject"}]}`. Process in one transaction, preserve order, accumulate submitter rewards, and roll back if any item fails validation, is missing, is finalized, or cannot persist notifications. Duplicates return 400 with exactly `Duplicate candidate restaurant id`. Success returns `{"success":true,"data":[...]}` in request order.
