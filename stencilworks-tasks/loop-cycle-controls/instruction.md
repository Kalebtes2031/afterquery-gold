Add cycle controls so templates can alternate values without counters. `{{ loop.cycle(...) }}` works inside a loop: it picks by the current loop index, wraps when values run out, and with no arguments renders an empty string. Nested loops use the innermost loop. Existing `loop` fields stay unchanged. Calling `loop.cycle` outside a loop must fail with an error that says it has to be used inside a for loop.

Also implement `{% cycle ... %}`. Anonymous tags work only inside a loop, share that loop's cursor, advance only when rendered, and reset for each new loop. Named groups use separate case-sensitive cursors, can continue outside loops (including at the template root), and keep going across separate loops in one render. Named and anonymous cycling stay independent. A leading identifier followed directly by another value is the group name; a lone identifier, or identifiers separated by commas, are values. Both forms take normal expressions (numbers, filter pipelines) and emit the chosen value with no extra separators. Trailing commas add no extra value.

Cycles should work inside `if`, `with`, `filter`, and `{% block %}` bodies. An empty `{% cycle %}` is a parse error. Anonymous tags may parse at the template root but must fail when rendered. Empty loops and their `else` arms do not advance cycle state; each new render starts fresh. Text inside `{% raw %}` stays literal and must not affect a following real cycle. Parsing and outline must recognize cycle tags: anonymous ones outline as `cycle N` where N is the value count, and named ones as `cycle <name>/N` — for example `{% cycle band "1", "2" %}` outlines containing `cycle band/2`.
