Template inheritance should let a child wrap the parent block body instead of only replacing it.

Implement `{{ super() }}` for use inside a block that overrides a parent block with the same name. It renders the nearest parent definition for that block, then the child continues. In multi-level `{% extends %}` chains, each level's surrounding text stays in order: a grandchild calling `super()` sees the child's wrap around the grandparent content. Calling `super()` outside an overriding block, or when no ancestor defined that block name, is a positioned template error naming the template and pointing at the call. Nested blocks each maintain their own parent stack—a nested `super()` must not pull the outer block's parent. Multiple `super()` calls in one override re-render the same parent body each time without consuming loop state. Empty parent blocks render as empty string through `super()`, not an error. `super()` accepts no arguments.

Existing inheritance rules stay: `{% extends %}` must come first, child text outside blocks is dropped, depth limits unchanged. `include`, filters, escaping, and `loop` behave the same inside parent bodies rendered via `super()`. Templates that never call `super()` keep current output byte-for-byte. `stencil check` and `stencil outline` accept well-formed `super()` syntax; illegal uses fail at render time with caret diagnostics.
